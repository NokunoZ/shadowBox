# code/runTest/ — demo and scoring

Two different jobs live here. They are easy to confuse, so keeping them straight
matters.

## TestRun.py — the live demo

*Capture video, show which class is firing and its confidence.*

- **in** — webcam (or a video file, useful for repeatable debugging)
- **out** — an on-screen overlay. Qualitative only, produces no numbers.

Runs both stages per frame on a rolling buffer of the last T frames. Must reuse the
exact preprocessing from training — see `code/noted.md`.

**Labels come from the checkpoint, not from the dataset folders.** Classes are
declared by folders in `dataSet/`, so that directory can gain a class at any time —
scanning it here would map output index 3 through today's folder list while the
loaded model was trained against last week's. The overlay text, the class colours and
the legend all key off the checkpoint's stored class list, and a new class shows up
in the demo with no edit to this file.

Two things to get right:
- **Speed.** YOLO-pose plus the classifier every frame may not hold real time on CPU.
  If it stutters: use the smaller pose model, or classify every N frames while
  keeping the pose running every frame.
- **Flicker.** Frame-by-frame argmax jitters between classes. Smooth over a short
  window, and stay silent below a confidence floor rather than guessing.

## getTeststatistic.py — the score

*Percentage of correct guesses, into `confident.csv`.*

- **in** — `trainDataSet/testData/` (labelled clips)
- **out** — `confident.csv`

### The mismatch worth settling

The two files as described do not connect. `TestRun.py` reads a webcam, which has no
ground truth, so nothing downstream of it can compute "correct". Accuracy has to come
from the labelled `testData/` split instead.

So `getTeststatistic.py` should be a separate offline pass over `testData/` — not a
consumer of `TestRun.py`'s output. `TestRun.py` stays a demo; this stays the metric.

Because the class list is whatever the checkpoint says, this script must also
**verify the folders match**: if `testData/` contains a class the checkpoint has
never seen, or is missing one it expects, stop and name the difference. Scoring a
six-class model against a seven-class test set produces a real-looking number that is
meaningless.

### confident.csv

Currently empty and now gitignored, since it is regenerated output. Suggest one row
per test clip — `clip, true_label, predicted_label, confidence` — rather than a
single summary number. Per-clip rows let us find *which* moves fail; a lone accuracy
figure does not. A confusion matrix on top of that would show, for example, whether
Cross is being read as Jab, which is the likely failure given how similar they are.

Rows carry the label **names**, never bare indices — an index in a CSV is unreadable
once a class has been added. The confusion matrix is sized `n x n` from the class
list, and the per-class breakdown is generated by looping over it, so adding a class
widens the report automatically instead of silently dropping the new row.
